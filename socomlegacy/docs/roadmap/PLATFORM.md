# The platform matrix: each subsystem, its package, its status and the test that holds it

A living table (PLAT-01, [01-platform.md](01-platform.md)), written 2026-10-01 on web sprint 6's branch. It owns one
mapping: **subsystem -> package and path -> status -> tasks -> the test that validates it**. Screens and their captures
are not here: PLAT-31's golden manifest owns *screen or state -> capture path -> method*, and a row below cites it, never
repeats it.

How to read and keep it:
- **Paths** are relative to `redotcom` (this project). What exists **today** is named by its path; a subsystem not
  built yet names the package web sprint 6's ruling W6.R2 assigns it
  ([`../plans/2026-10-01-web-sprint-6-foundations.md`](../plans/2026-10-01-web-sprint-6-foundations.md)), as PLAT-02's
  spec writes it up ([`../specs/2026-10-01-web-sprint-6-package-boundaries.md`](../specs/2026-10-01-web-sprint-6-package-boundaries.md)):
  `packages/ui` (`@s2u/ui`: dialog loader, zAnim runner, valves and UI variables, host command table), `packages/fmv`
  (`@s2u/fmv`: PSS demuxer, decoder wrapper, player semantics), `packages/card` (`@s2u/card`: storage interface, slot
  store, card filesystem, libmc, scrambler, save modules); the ZAR and rdr writers beside their readers in
  `packages/archive`; streams inside `packages/sound`. Where W6.R2 assigns nothing, the cell says so. The three new
  packages are scaffolded (PLAT-02, merged), each with a headless test, and now hold sprint 6's merged work: `packages/ui`
  the valve store and the UI variables (`packages/ui/src/valves.ts`, `packages/ui/src/uiVars.ts`, PLAT-09) and the load
  phases (`packages/ui/src/loadPhases.ts`, PLAT-29a); `packages/card` PLAT-24's modules and the slot store
  (`packages/card/src/cardSlots.ts`, PLAT-25); `packages/fmv` the PLAT-19a spike's wasm glue and build
  (`packages/fmv/wasm/glue.c`, `packages/fmv/wasm/build.sh`) and PLAT-18's PSS demuxer (`packages/fmv/src/pss.ts`). *(Corrected by the sprint 6 close review, 2026-10-02: this
  read "each is an empty `src/index.ts` and a headless test so far".)*
  **Corrected by R7 (W6.R10, 2026-10-01):** W6.R2's card filesystem and scrambler in `@s2u/card` and the ZAR and rdr
  writers in `@s2u/archive` are void -- R7 dropped PLAT-37 and PLAT-27; `@s2u/card` keeps the storage interface, the
  slot store (two virtual slots in localStorage), libmc and the save modules as JSON, and the disc's ZAR and rdr
  readers stay in `@s2u/archive`.
- **Status:** **built** (the subsystem does what the original does, for what SOCOM Legacy uses it for), **partial** (a
  piece exists, usually ARMORY-only or match-only, and the task makes it general), **not built**.
- **Validated by** names the test file(s) that hold what exists to the original. A row with no such test is marked
  **UNVALIDATED**: that includes every subsystem not built, and a built piece whose tests do not exist. A test of a
  stand-in (redotcom's own lobby for the original's online screens) does not validate the original's subsystem and is
  named in the subsystem cell, not here.
- **Tasks** are the roadmap ids that own the subsystem's gap; the segment file's task block is authoritative.
- **The check:** `tools/test/roadmapGraph.test.ts` ("the capability matrix") fails when a path named here is not in the
  tree, a row names neither a test nor UNVALIDATED (or both), a status is not one of the three words, a task id is no
  active task (a future-scope or dropped id included: R7 dropped PLAT-27, PLAT-37 and OPT-08 on 2026-10-01, and their
  rows say so in the subsystem cell, with "none" for tasks), or an active task is in no row. Five tasks own no subsystem
  and are listed in the test with the reason: the four owner windows (BOOT-01, OPT-19, ONL-32, PLAT-36: captures and
  traces, PLAT-31's manifest) and PLAT-35 (documents only). Correct a row when its task lands; never delete one.
