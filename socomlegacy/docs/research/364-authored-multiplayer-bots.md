# 364 -- Authored bots in Frostfire multiplayer

## 1. Scope and provenance

The completed bot-port interview and [Frostfire plan](../plans/2026-10-20-frostfire-bots.md) authorize this optional authored browser extension. It is not recovered SOCOM II campaign AI. The source donor is the local socom-unzipped checkpoint 9f95a7e plus its preserved working-source snapshot source-20261020T223735Z. That unpublished local source is provenance for newly authored code, never a desktop evidence citation for a retail fact.

Online bots occupy normal Room seats and emit the existing command, fire, reload, door and loadout requests. Movement, collision, weapon/cone checks, ammunition, hit/death reactions, animation and the respawn round's rules remain (a classic game has no bots: H315, BOTS-LAND) the existing Redotcom implementations. One human can host a match; humans and CPUs share at most eight places per team. No Shipment FFA rules or unlimited reserves are imported.

## 2. Navigation and boundaries

Navigation uses the current Walker for clearance and validates prepared version-2 graphs. Graph creation is explicit setup work outside the live tick. The inherited local MP2 cache was version 1 and was rejected; the rebuilt graph has 10,044 nodes and 57,701 edges. Offline preparation took 27.8 seconds on the development host; this is setup time, not per-frame performance. A route between the opposing first spawn areas has 73 waypoints. The ignored derived JSON is local game data and is never committed.

From `socomlegacy/`, run `npx tsx tools/prepare-bot-navigation.ts` once before the first bot playtest, or again after collision/navigation changes. It reads `SOCOM_DISC` when set, else the existing `public/maps` extraction; an explicit extracted-disc directory may be its sole argument. Both the tool and the game respect `S2U_BOT_NAV_DIR`, otherwise using ignored `public/maps/nav/MP2.json`. Restart the local server after regeneration. No graph is generated by a live room.

Without a valid prepared graph this host offers no bots (`RoomBots.for`, the merge controller's ruling on BOTS-LAND's review (b) 6; LATER 388, 389 follow). Objective tactics, autonomous ladder/climb planning, autonomous grenade/explosive tactics and exact posed-weapon muzzle fidelity remain outside this first slice. A headless origin must still satisfy the existing Room's reach, wall and cone checks; no check is relaxed for CPUs.

## 7. Living spawn stalls and upright corpses (FBA.R14)

A native one-human/fifteen-CPU MP2 trace showed a living advancing SEAL at exactly the same feet from 10 through 60 simulated seconds. A reduced public Room/MatchBots case reproduced the stop on an open floor without motion data: a stationary ally ahead renewed the same twelve-tick traffic wait forever, before separation or recovery could run. Moving the ally sideways let the same CPU continue, distinguishing traffic policy from a collision or animation defect.

The authored correction waits once, then first checks whether the existing planned leg already clears the unchanged native mover and all teammate segments. A nearby off-axis ally inside the broad traffic cone need not obstruct that leg. Otherwise it commits to a checked local passing leg; a moving leader retains normal follower priority. `TRAFFIC_ADAPTATION.passDistance` is an authored 24-world-unit passing displacement; the existing twelve-tick initial wait and eight-unit overlap clearance remain. These are bot policy, not values claimed from the original game. Synthetic two-faction, priority, one-wall and blocked-corridor cases hold the policy and safety.

The first eight-second departure check missed a later stop where both sideways legs hit native walls. A bounded geometry probe showed that the original forward legs were walkable and cleared the stationary ally by 14.53 and 10.00 world units at the two observed stopped poses. A fast captured-pose native regression now holds this case. The all-seat MP2 regression checks both departure and progress during seconds 20–25 for all seven/eight CPU spawn slots. It includes travel during an investigation/contact phase and excludes deliberate holds/cover/engagement, so a bot moving a little before freezing cannot pass it merely by changing its intent label.
