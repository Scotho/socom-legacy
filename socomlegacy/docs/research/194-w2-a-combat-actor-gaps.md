This closes meaningful feasibility: the ordinary gun model, pickup box, slot classification, ammo pool, primary authority and request/accept path exist in retail. No new authored art is needed for the basic lifecycle. It does **not** justify copying the original owner-peer network trust into the web server.

**Implementation proposal.** Introduce a server-owned world inventory entity with `{roundEpoch, entityId, kind, itemId, ammoEntries, transform, state}`. Keep dropped ammunition quantities and compatibility separate from the weapon model. Perform a single validated transaction that claims an object, replaces the current in-round slot, spawns the replaced item/bundle where the original policy requires, updates the live kit and removes/transforms the claimed entity. Publish a kit revision plus world-entity deltas; joining pages receive the current set. Leave saved armory/loadout preferences unchanged unless the original saved-profile path is separately established. The port's current “new weapon name → fill mags” behavior must not create ammunition during a pickup.

Share actor eligibility with A02 instead of creating another independent `alive && near` predicate. Include stable entity/generation identity so a request cannot consume a new object after a round reset or ID reuse. Death-drop suppression in respawn is a **retail rule**, not a proposed anti-farming policy. Centralized serialization of two competing requests and reconnect restoration are web adaptations.

**Meaningful acceptance tests.** Classic death creates one eligible primary/secondary drop set and a bundle with the actual remaining rounds; a second death tick creates none. Respawn-mode death creates none. Taking a compatible weapon replaces the live slot without saving a new armory preference or granting default ammunition. Two actors requesting the same entity yield one accepted result. Ammo auto-pickup transfers only compatible/capacity-eligible entries and leaves residual entries; replaying an acceptance cannot duplicate ammo. A dead taker, out-of-range actor, disallowed motion, consumed object and stale round epoch are refused. Swap model/HUD/muzzle/records/ammo and remote kit agree after acceptance. Late join gets existing drops and current replaced kit. Launcher pickup/drop gets its own case rather than inheriting rifle refill behavior.

**Still owed.** Exact ammunition capacity redistribution and partial-entry semantics through `005bb000`/`005ba770`; all slot compatibility categories; model settling/rotation and expiry; pickup owner departure/transfer; teardown between classic rounds; the exact prompt tie-break and scene occlusion pass. The already sourced owner/serial scheme is not proof of reconnect behavior. Capture a classic two-client death, an exchange to a different rifle, two simultaneous requests, an ammo-only pickup and a respawn-mode death, recording the pickup object and ten magazine slots. Do not implement arbitrary item lifetime or full-mag transfer to fill those gaps.

## 3. A02 — missing motion `NoFire` and actor eligibility

**Current PORT.** `viewer/src/motionTable.ts:28` describes motion fields, and `:108` reads them; `NoFire` is left out. `viewer/src/main.ts:442–454` connects `Fire.ready` to swap/dead only, and `walk.ts:628` returns the aim while walking without a combat-action test. The room's corresponding checks at `match/src/room.ts:1468–1492` cover alive/round phase, rate/ammo/reload, swaps, launcher and binoculars. `viewer/src/net/shotCone.ts:57` / `:84` retains posture/airborne/swap state but not a general action/fire permission at the command. This omission is not cured by the weapon's rate limiter or shot-cone validation.

**Primary consumer closure.** `00287620` reads key string **NoFire** (ELF 0x3ef9f8) into motion-data `+0x2c`: absent → 0; bare → 1.0; numeric → supplied float (D:L131397–131429). `005c0ae0`, L476375–476378 and L476442–476444, calls `005a7de0` for fire permission. That function:

- accepts only actor states 0, 1, 2, 3 or 6 at L462612 before further checks;
- rejects the named throw/toss motions, reload/swap action family and several paired/CQB states at L462620–462678;
- checks further actor/link/overlay gates at L462679–462694;
- for the ordinary firearm branch, compares the playing motion's phase with each leaf motion's `+0x2c`, via `0058a8c0`, L462695–462705. Not every equipment class requests the same phase gate: `005c0ae0` passes a different selector for classes 0x79/0x97. Preserve that distinction rather than applying a universal firearm rule to every device.

`scalar.txt` executes the retail predicate directly. Forward play allows fire only at **phase > NoFire**, not equality. Reverse play allows **phase < 1 − NoFire**, not equality. Bare NoFire=1 refuses through phase 1. Numeric thresholds therefore matter; a boolean `busy` gate would be wrong.

Independent retail field reads in `actor-data.json` provide immediate regression cases:

| Clip | NoFire | Consequence for the phase consumer |
|---|---|---|
| `seal_stand2prone` | bare / 1 | The transition does not allow ordinary firearm fire merely because posture already changed. |
| `seal_crouch2prone` | 0.8 | Forward fire becomes eligible strictly past 0.8, subject to the other gates. |
| `seal_land_hard` | 0.3 | Partial landing lock, not a whole-clip or whole-airborne ban. |
| `seal_hang`, `seal_hang2climbup`, ladder-slide clips | bare / 1 | Traversal needs actor-state/clip eligibility. |
| `seal_place_claymore` | bare / 1 | Firearm permission must agree with the place action. |
| `seal_jump`, `seal_land_soft`, six short multiplayer flinches | absent / 0 | Their presence does **not** establish an entire-clip fire lock; do not introduce one. |

The numeric slots in `DAT_003d...` are runtime-resolved. `motion.txt` reads the **initializer calls** and their ELF string operands; it does not pretend the ELF's 0xffff/zero static slots already contain live names. These resolve the throw/toss, launcher-transition and turret-transition families, as well as the flinch gates used by A03.

**Implementation proposal.** Add `noFire: number | null` with the existing absent/bare/numeric distinction. Build a shared actor-action capability calculation over raw actor state, current motion/phase/direction, overlay/reload/swap/equipment state and relevant links. The client uses it before producing a shot or reload; the server records the same permission at the command used by fire validation. Do not validate historical shots using only the actor's current presentation state. The server's authority and replay rules are adaptations, while the permission calculation is sourced retail behavior.

**Acceptance.** A rifle round attempted during stand→prone, hanging and ladder-slide is refused without consuming a round; crouch→prone at exactly 0.8 is refused, just past is eligible if all other gates pass; reverse direction uses the complementary strict boundary. Hard landing tests cover before/equal/after 0.3. Jump and short flinch cases verify that no blanket `airborne` or `any action` rule was added. Local effects, ammo consumption and server acceptance stay consistent. Delayed fire submitted after the motion ends still uses its command-time state. Test swapping, throwing, launcher transitions and binoculars against the same capability table to prevent regressions in already implemented gates.

**Owed.** Full mapping of remaining raw state/mask/link fields and phase traversal across multiple blended leaf motions (the decompiled loop overwrites its result; do not assume an AND over every leaf); original captures at selected clip boundaries; classification of equipment exceptions. The scalar test closes the comparator, not the entire action scheduler or the visual blend. No console parity is claimed.

## 4. A03 — flinch reload refusal is gameplay state

**Current PORT.** `Room.flinch` at `room.ts:1589` only broadcasts `{id, clip}`. Protocol at `net/protocol.ts:569` has no authoritative phase/tick or capability state for the event. `remotePlayers.ts:141–180` / `walk.ts:262–274` play the clip over ground play; `Room.reload` at `:2080–2105` checks reload/swap/airborne but has no flinch state.

**Covered consumer, independently reread.** `005a2690` starts the flinch and sets motion flags **mask 0x4** and **mask 0x2** (D:L460018–460025). `005b4340(actor, 3)` refuses when the top motion carries **0x4** at L469494–469504. Both the reload-start path `005c2a90`, L477394–477407, and reload animation selection `005a82e0`, L462814–462819, call this action-3 gate. A reload attempted while that flinch motion remains active can therefore be refused even though the actor is alive, grounded, not swapping and has spare magazines. C1/E already closed this part of PORT-91's “flag readers unread” ledger; the wave-2 addition is its explicit dependency on A02's shared gameplay permission state.

Do **not** rename mask 0x4 to “all input blocked”: another consumer at `00577ea0`, L437462–437467, changes animation composition; the flag does not itself prove a trigger/stick/look ban. The short flinches have no NoFire, and A02's independent fire predicate remains necessary. Mask 0x2's complete role and the flinch's interrupt/stack behavior are still owed. In particular, `00587c20` walks a leaf-motion object; its `+0x28` must not be equated to the top motion's same-offset field without a structure trace.

`motion.txt` also closes the names behind several old flinch gates: `003deed0/d8` are Fall forward/backwards; `003dee08/20/48/40/18` are Stab/CQB attack/Apply restraints/Receive restraints/Stabbed; `003dee30/38` are Death stand head01/head03. These are names from initializer operands, not inferred from a nearby animation. Their existence does not make campaign-only actions online requirements.

**Implementation.** Treat a selected flinch as an actor-action transition, carrying the authoritative tick/clip/phase policy needed by the shared capability layer. Preserve the existing health-loss-only trigger (armour-only hits do not flinch) and existing online rejection of the three long hits. Apply the same active-motion permission to local reload and room reload. A ticked flinch event also gives presentation a way to align with delayed body interpolation, but the event-timing choice is a web networking adaptation.

**Acceptance.** Hold a short flinch active on a grounded actor with a spare magazine: reload is refused and no magazine/audio transition occurs. After the source-consistent end/interruption, reload succeeds. Fire is tested independently; no all-input freeze is introduced. A death, respawn, new round or superseding movement action clears old action state. Armour-only hits, repeated hits during a protected motion and delayed events are covered. Runtime captures owe the exact interruption frame and priority during a moving reload, throw, stance change, scope and ladder.

## 5. A04 — blast and traversal must arbitrate one actor

The existing `KNOCK_IN_MOVE_PLACEHOLDER` at `viewer/src/net/blast.ts:137–144` returns false whenever traversal is busy; the room uses that at `room.ts:2058`. This is already identified in prior work, not a newly found mechanic. The important integration distinction is that `Room.kill` at `:2131–2144` already releases traversal for **death**. That does not repair a surviving actor's blast reaction.

`0057e770`, D:L440981–441027, releases the paired/link state via `0057ee00`, completes a pending weapon/launcher switch via `005a5da0`, dismounts a nonzero turret/link through `00545ee0`, unwinds the motion stack, then selects the alive/dead/prone reaction. The early draft misattributed `005a5da0` to ladder release; its switch checks/callbacks are at L461653–461756 and C1/E correctly separates them. The overall knock path can replace traversal, but the exact remaining ladder state is still a capture gate. In the prone living branch it starts the dedicated cover motion and sends motion kind 0x22; it does not merely omit all response because the normal standing knock is inapplicable. PORT's `blastKnock` returns null for prone under `PRONE_COVER_PLACEHOLDER`.

Implement release → authoritative reaction → mover/collision transition as one ordered operation, shared with A02's capability state. Preserve the existing difference between lethal and nonlethal landing/get-up. Tests need surviving ladder and hanging victims, lean, turret when available, prone cover, and a blast arriving during a throw or reload. Assert final attachment state, position/velocity, grounded/airborne status, fire/reload permission and exactly one reaction event. A death-triggered release test alone is insufficient. The exact priority for every overlapping action and the prone clip duration/phase remain capture gates; C1/E already supplies clip/animset leads.
